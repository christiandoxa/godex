# Prodex 0.437.10 behavioral parity checkpoint

Canonical reference: Prodex tag `0.437.10`, source commit
`c047ec437bc87cc19d22064f9946db5d446d9a45`. The official Linux x86_64
release executable reports `prodex 0.437.10` and has SHA-256
`daa8e4bf2527b68e3cf501e144551e438b0583e9da3c42b896cb1bf600817bb2`, matching
the published `SHA256SUMS` entry and release manifest.

The 0.437.9 to 0.437.10 runtime delta is goal attachment persistence across
temporary overlay removal and resume. The reference repairs goal rows without
waiting for the exclusive rollout maintenance lock, prepares saved goals for a
picker or fresh runtime launch, repairs nested references inside generated
`goal-objective.md` wrappers, and conditionally updates only the objective value
that was read. Raw pasted text and image bytes remain opaque.

Godex reuses its existing shared Codex filesystem boundary for this behavior:

- `MaintainManagedSessions` repairs goal rows before trying the rollout lock.
- `PrepareSharedSessionHome` repairs goal rows for fresh and picker launches.
- Generated wrappers are read with the existing bounded no-follow attachment
  reader, rewritten atomically, and rechecked before the write.
- Goal SQL updates include the original objective in the `WHERE` clause, so a
  concurrent status, budget, timestamp, or objective replacement is preserved.

## Evidence

Source-contract regressions are covered beside the Codex gateway:

- generated wrapper repair preserves nested attachment bytes and leaves raw
  pasted files unchanged;
- a stale compare-and-swap update cannot overwrite a newer objective;
- goal repair completes while a child holds the rollout maintenance lock;
- existing symlink, bounded-read, atomic-write, and session path tests remain
  active.

The focused command is:

```text
go test ./internal/gateway/codex -count=1 -timeout=30s
```

The release-only binary differential is pinned by
`scripts/verify-release-parity.sh` to the source commit and SHA above. It runs
the managed-profile, CLI, native-context, provider, and continuation harnesses
against the verified official executable. Those harnesses do not certify live
provider accounts, every native TUI path, or all attachment bytes; the wrapper,
lock-contention, and compare-and-swap contracts are proved by the local gateway
tests above.

This checkpoint does not authorize a release tag. It records the verified
0.437.10 oracle and the implemented attachment-recovery delta while broader
provider and live-auth limitations remain under their existing checkpoints.
