# Prodex 0.437.12 — Godex behavioral parity checkpoint

Canonical Prodex is the 2026-10-14 tag `0.437.12`, source commit
`e9d5a16f9abec6976cd670021c1e7f0b04a67b69`. The published Linux x86_64
executable reports `prodex 0.437.12` and has SHA-256
`ecab17893af7142304072c74c7af723347712a4fa5d055142e7c5035727d9d63`, matching
the `SHA256SUMS` entry and `release-manifest.json`. The manifest binds that
asset to the same source commit, Mojo `1.1.0`, and `GLIBC_2.23` minimum.

This checkpoint audits the exact `0.437.11..0.437.12` source delta against
Godex `origin/main` at `9b9b5350d58e8af4cd43822b413a6ba0613e638b`.

## Delta audit

The generated changelog at the tag contains one release item:

```text
Keep saved session IDs readable after Super exits (f35210d)
```

The release notes explicitly say that there are no new flags and no saved
session storage-format changes. The user-visible contract is an interactive
Super exit footer:

- After the final successful child exit, Prodex appends plain text to the
  existing native usage/session output. It does not open another inline
  Ratatui viewport, query or move the cursor, clear the screen, truncate to
  terminal width, or advertise the deleted temporary socket.
- The footer is emitted only for a TTY launch and is suppressed for piped or
  non-TTY execution. Automatic relaunches do not emit an intermediate footer.
- The launch's root-session notification supplies the canonical UUID. The
  footer prints that complete UUID and a copyable `prodex s <uuid>` command on
  separate lines. If the hook did not report an ID, a validated explicit
  resume ID may be used; otherwise the footer says that the session ID was not
  reported and offers `prodex s resume` without guessing from another
  terminal's latest session.
- The launch-owned marker, offset, lock, and overlay are read and then cleaned
  after their final consumer. Saved conversations, attachments, and paused
  goals remain intact; a paused goal remains paused until `/goal resume`.

The source tests in the release notes cover exact IDs, append-only output,
unknown and invalid identities, root-marker precedence, marker cleanup,
broken pipes, and recording a fresh Super identity while automatic rotation is
disabled. The release notes report 6 saved-session regressions, 17
child-process/terminal lifecycle tests, 73 runtime-launch tests, 386
Mojo-core tests, and workspace Clippy with all targets/features and warnings
denied. The binding decoder's negative, out-of-range, duplicate, known-profile
sample-index, and invalid-profile-total checks remain enabled.

The rest of the tagged source diff is release metadata and implementation
movement: Windows x64 release-calibration workflows, release/cache/shard
changes, package-version updates, and migration of terminal layout, transcript
normalization, and runtime-doctor parsing/reduction policies into compiled
Mojo adapters. Those commits split files and preserve the existing test
contracts; they do not add a release-note command, flag, or persistence
feature. They still require source-contract review if Godex claims parity for
those broader diagnostic and TUI surfaces.

## Godex baseline and current gap

Godex's release-only script now pins the Prodex `0.437.12` source commit,
binary digest, branch, release URLs, manifest, and `prodex 0.437.12` version.
It retains the prior 0.437.11 focused stages and adds a fail-closed
`TestProdex043712...` stage for the saved-session contract.

The Unix gateway restores the inherited terminal and removes the owned
app-server socket before emitting the new footer. It allocates a private
launch marker only for interactive companion launches, injects the existing
hidden SessionStart/notify callback shape without replacing configured notify
handlers, and reads the bounded marker before its deferred cleanup. The footer
requires stdin, stdout, and stderr to be TTYs, preserves explicit resume IDs as
a fallback, and offers the picker when no safe identity is available. Focused
tests cover CRLF append-only rendering, marker bounds, companion-only tracking,
TTY lifecycle, non-TTY execution, and failed child status.

The next gate must update the source, manifest, checksum, and `--version`
pins to the values above and add a fail-closed focused stage for the new
footer contract. That stage should cover:

- root-marker identity taking precedence over a resume argument or any global
  latest-session lookup;
- validated explicit-ID fallback and the unknown-ID picker message;
- fresh Super marker allocation with `--no-auto-rotate` and without a
  recovery monitor;
- append-only output with the exact UUID and command, no escape sequences or
  socket URL, and no intermediate output during relaunch;
- cleanup of only the launch-owned marker, offset, lock, and overlay while
  preserving saved data;
- final-exit timing, terminal restoration ordering, TTY/non-TTY behavior,
  broken pipes, and child exit-status preservation.

The existing 0.437.11 routing, Gemini, profile, CLI, context, DeepSeek, and
WebSocket stages should remain in the gate unless a separate audit changes
their contracts. A broad binary differential still cannot certify live
provider credentials, every native TUI/app-server transition, or all
platform-specific process behavior. This audit did not run `make verify` or a
0.437.12 release gate, and it created no tag or release.
