## Tagged observable delta

The 0.437.14 release notes describe a causal **authenticated quota-probe
recovery** for a previously empty profile pool: after successful quota
observation with the *same credentials*, older local auth backoffs and matching
quota quarantine can be retired. Quota observations must not override a newer
401/auth failure, newer snapshot, rotated credentials, transport cooldown,
replay affinity, or a profile still quota-exhausted. Startup revalidation must
run even when an inherited quota cache is fresh but auth failure persists;
background workers release queue admission and notify waiters.

The release also moves `Retry-After` header and message token parsing to
compiled Mojo, including case-insensitive ASCII marker matching, Unicode
whitespace, unsigned integer caps and ceil-to-millisecond fractions. Internal
runtime-doctor rendering and Mojo migrations are not themselves proof of any
additional Godex user-visible behavior.

### Probe result arbitration checkpoint

Concurrent Go quota queries used completion time to decide which successful
response populated the live cache, allowing a delayed exhausted response to
replace a newer ready response. A per-Status monotonic generation is now
issued when each actual fetch begins; serialized application refuses older
successes, including their durable snapshot writes. Read-only caches and
persisted snapshot fallback are not proof of fresh authenticated credentials.
The concurrent regression forces opposite completion order and verifies both
live and persisted latest data. This is **not** a completed implementation of
Prodex's credential-bound auth backoff recovery.

### Authenticated quota recovery integration checkpoint

A successful HTTP quota request now has an optional **non-persisted**
credential-bound receipt: the gateway hashes the exact request's bearer token
and account ID, rechecks active credentials after the 2xx response, and rejects
changed tokens, changed account IDs and HTTP 401. Ordinary cached/persisted
usage DTOs cannot create recovery receipts. The quota gateway now also follows the tagged 0.437.14 unauthorized
retry contract: after a 401, it reloads a changed local credential, then
optionally uses the explicit auth refresher after another 401; the successful
request's **final** identity is returned with its quota receipt, not the
failed original token. A fresh post-response read rejects a concurrent
identity swap, and a terminal 401 cannot produce a recovery receipt. The
fail-before `TestProdex043714QuotaUnauthorizedReloadUsesAcceptedIdentity`
and `TestProdex043714QuotaUnauthorizedRefreshUsesAcceptedIdentity` now PASS,
including exact upstream request order, final token digest and no same-token
blind replay. These are local loopback HTTP tests, not yet a cross-binary
full account-recovery oracle.

The quota use case schedules
authenticated revalidation off the hot path and stores only verified receipt
metadata with a finite lifetime; an accepted newer usage observation
invalidates earlier proofs. Request routing records which credentials actually
received a 401 and then retires only a strictly older matching **auth** lease
once a fresh ready receipt passes the 0.437.14 Mojo decision rules. Generic
retry, quota, transport, route circuit, and continuation ownership are not
removed. Tests reject forged/old/rotated/unknown proofs and preserve a separate
non-auth quarantine. An early same-second receipt does not falsely retire a
newer 401; later request-driven revalidation is throttled at two seconds,
preventing probe storms while allowing eventual recovery. A bounded wait (up
to 850 ms) for queued probe progress is permitted only while the pool is
auth-quarantined and uses a verified optional progress interface. Progress
alone never grants eligibility: an end-to-end local Router test requires the
new authenticated proof and asserts exactly one successful upstream dispatch,
while the matching negative control sends no upstream request. All these
focused regression and race tests passed. These are local synthetic tests,
not an independent 0.437.14 three-profile executable oracle.

### Current-credential confirmation after a 401 and subsequent rotation

The tagged 0.437.14 `same_credentials` policy checks the credentials active
when the successful quota observation is applied, not equality with a
superseded bearer that previously received HTTP 401. Godex now permits a
confirmed new credential to retire that *older* auth-only penalty once the
observation passes recency and quota guards. The live quota adapter re-reads
the current credential digest before allowing a stored receipt to be used;
changing credentials yet again invalidates and deletes the proof, so restoring
a previous token cannot reactivate a revoked receipt. Generic retry leases,
quota exclusions, continuation affinity and transport failures remain intact.

Source-aligned regressions include
`TestProdex043714QuotaCurrentIdentityTracksRotatedCredential`,
`TestProdex043714QuotaRecoveryReceiptRejectsCredentialChangedAfterProbe`,
the old-failure/new-verified-token scenario in
`TestProdex043714AuthenticatedQuotaRecoveryOnlyRetiresOlderMatchingAuthQuarantine`,
and the complete three-profile quota-transition test. Local focused and race
tests PASS. This expands in-process recovery evidence; the full cross-binary
three-profile recovery sequence and inherited auth state across restart are
still not certified.

This intentionally fails closed and does **not** certify full Prodex auth
parity: Godex currently lacks a durable inherited auth-penalty format and a
cross-binary end-to-end three-profile reset/recovery differential.

### Three-profile quota transitions after an authenticated receipt

A second quota-cache generation fence now makes successful observation
revisions visible to routing **per profile**. A fresh Pro Lite quota result
invalidates only its previous Router cache entry, not any unrelated quota
failure or transport retry state. The tagged three-profile transition is
reproduced locally with a historical Pro Lite auth penalty: main is initially
selected, then main weekly and second five-hour exhaustion leave only Pro Lite
ready; an authenticated same-credential probe releases the old Pro Lite auth
penalty, and both Responses and Compact dispatch there. After third weekly
exhaustion, second's five-hour recovery dispatches the next turn, then main's
weekly recovery dispatches the final turn. Upstream exactly-once sequence:
`main,third,third,second,main`. Two additional regressions verify a newer
quota observation invalidates only its profile's cached availability, and a
rejected older generation never advances the observation revision. All tests
passed with the race detector. This is local end-to-end coverage, **not** an
independent two-executable tagged runtime proxy differential.

### Restart-safe 401/403 auth-health persistence checkpoint

A tagged Prodex 0.437.14 restart gap was reproduced in Godex: an active auth
penalty previously existed only inside the Router process, allowing a new
process to select a blocked profile without obtaining an authenticated quota
receipt. Godex now stores a bounded, private, versioned `auth-backoff.json`
state separately from all generic retry and transport cooldowns. It includes
only account label, failure timestamp, deadline and merge-safe clear epochs;
no bearer, OAuth token, credential fingerprint or raw auth record is written.
The auth TTLs reflect tagged production effective-score duration (401: 12 ×
300s = 60 minutes; 403: 2 × 300s = 10 minutes). At restart, a historically
blocked profile stays excluded even if a persisted quota DTO still says ready.
A new, credential-bound authenticated quota revalidation is scheduled, and
only a causally newer accepted receipt may conditionally retire the exact
persisted auth generation. Generic retry, route circuit and transport state
are preserved across clearing and subsequent restart. A newer 401 from a
second process defeats an older process's clear by an on-disk epoch fence;
delayed old writes cannot resurrect previously cleared failures. Corrupt or
unsafe primary files recover only from a separately validated private
last-good backup; if both are invalid, startup fails closed.

Focused integration, tampering, concurrency-generation and expiry tests are
included in the pinned preflight gate. This provides **local multi-instance
restart persistence proof**, but not a full two-executable Prodex 0.437.14
three-profile authenticated-quota restart differential.

### Differential state-integrity maintenance after auth persistence

The first source/SHA-pinned 0.437.14 DeepSeek differential after commit
`d4861daf` reported unexpected fixture state: Godex creates a new empty
`state/routing-auth-backoff.guard` when its durable auth store is initialized.
No provider response mismatch was established by that failing run. The
oracle's allowlist is now limited to this **exact** coordination filename;
independent negative controls reject nonempty or public guard files and still
reject all `auth-backoff.json` data/backup files from a credential-free
DeepSeek key scenario. This is not blanket allowance for new persistent auth
state in arbitrary fixtures. The complete pinned DeepSeek comparison needs
to be rerun on a clean committed candidate before reporting PASS.
