## Tagged behavior delta

The release requires no new flags or saved-session storage format. Its
observable changes include:

1. **Normal-screen terminal restoration.** Post-child cleanup selects the
   normal buffer via `DEC 1047` instead of repeating `DEC 1049`, which would
   restore an obsolete saved cursor and overwrite the native usage summary or
   plain-text session footer. Mouse, keyboard, paste, focus, and cursor cleanup
   must still occur without clearing the main screen or flushing queued input.
2. **Transient observer descriptor pressure.** File-descriptor exhaustion,
   SQLite busy/locked/cannot-open, and temporary interrupted/would-block reads
   during session observation must not kill a healthy foreground child or
   consume unread terminal failure evidence. Retry is bounded, observer-owned
   optional SQLite handles are released, and permanent identity errors remain
   explicit; ambiguous observation is never permission to replay.
3. **Exact native WebSocket idle timeout.** The native string
   `stream disconnected before completion: idle timeout waiting for websocket`
   with `codex_error_info=other` permits terminal transport recovery, subject
   to session ID, terminal-event, accepted-work, goal-state, cancellation,
   retry and no-duplication guards. This does not fix the upstream timeout.
4. **DeepSeek stream tool argument validation.** The tagged Mojo policy now
   rejects unmatched Unicode surrogate escapes, finite-number overflow, and
   more than 127 JSON containers, mirroring serde_json semantics. The rest
   of the streaming tool call and failed-event envelope must remain intact.
5. **Hardening and internal reorganizations.** Tagged rustls 0.23.46 resolves
   four RustSec advisories in Prodex's Rust graph; Rust/Mojo extraction,
   diagnostic/provider changes, source-size splits and official Kiro 2.31.1
   release smoke pin are not automatically evidence of new Go requirements.
   Any changed observable provider or diagnostic behavior still needs tests.

Observer qualification: The legacy found-only reader API remains intact, and
runners prefer an optional richer observation contract when provided by the
production repository. A missing database is not confused with an IO failure.
The live observer fails closed on an unavailable database and resumes the
exact unread events when availability returns. This is not evidence of
identical Prodex observer error reporting or native-process orchestration.

Validation notes: `make verify` passed its format, source-size, framework,
vet, shuffled race tests and build at committed checkpoint `0ed5717a`.
The pinned release gate completed all focused new and inherited tests and
four independent executable comparisons before hitting an execution timeout.
Its DeepSeek `--scenario all` mode also exceeded the synchronous call limit;
all 18 scenarios were instead run individually against the exact same clean
candidate, pinned source and verified binary, each with its negative control
passing. This is separate-case evidence, not a single-process combined PASS.
Gemini `--gemini` completed with eight scenarios and zero differences, and
WebSocket `--websocket` completed its strict 41-attempt continuation suite.
Later checkpoint `2a7481e1` reran the exact Linux PTY oracle with an added
native-normal-screen case, bringing that oracle to **5/5 PASS**. The following
commits added four strict streamed DeepSeek tool-argument fixtures. Initial
binary-to-binary evidence reproduced different `response.output_item.added`
fields and Go-specific failure messages. After the production fix, all four
individual exact-binary fixtures passed with no observable differences and
negative controls covering event mutations, sequence numbers and framing.
These targeted passes are **not** a full release-gate certificate.
