## Tagged changes requiring qualification

The delta from `0.437.10` is a maintenance release with important
behavioral changes:

- Persistent **session release epochs** must fence stale owner snapshots after
  rotation, resume, same-second release/rebind and process restart. Immutable
  previous-response/turn-state ownership must remain protected.
- A **self-contained full-history** request may repair an old conflicting
  *soft* session routing hint. Opaque turn-state and previous-response requests
  cannot take that shortcut.
- Native TUI terminal restoration and mouse/paste/focus modes; app-server exit
  guidance and paused goals; preserved attachment and goal storage.
- Runtime doctor degraded-route and marker aggregation, provider configuration,
  DeepSeek/Gemini stream hardening, and quota rendering policy changes.

Other changes in the tagged diff move Rust policy decisions to compiled Mojo
without necessarily changing observable behavior. Audit such changes for exact
semantic deltas rather than copying code structure.

## Implementation checkpoints: session release and full-history recovery

Commits `aa30aa9` and `af5b435` implement two behavioral fixes from
the 0.437.11 tagged release notes.

**Durable session release:** Godex's version-1 routing snapshot now
retains a separate `session_release_epochs` map, atomically with the
active routing bindings and backup. An explicit deletion of a persisted
session binding installs a monotonically advancing logical fence. Old
worker snapshots cannot reinsert a session owner whose binding epoch
predates that release, while a subsequent **verified** upstream owner
may rebind with an epoch strictly above the barrier, including repeated
rotations in the same wall-clock second. The previous-response and
turn-state bindings are not silently discarded, and genuine conflicts
with no release still fail closed. The new snapshot field is optional
when loading legacy version-1 state.

Repository regressions failed before the fix on stale replay after
rebind and repeated same-second release/rebind, and now pass. Separate
tests verify a genuine unreleased conflict, backup restoration, invalid
release epochs, and rejection of malformed stale/verified updates.
The release fence is bounded by the existing routing snapshot size and
entry-count limits, but Godex has **not yet reproduced** the tagged
Prodex compaction policy for seven-day expired retired fences.

**Full-history soft conflict:** the Responses preflight now releases a
genuinely conflicted *soft session* only when its input has
reconstructable full history and no hard previous-response, turn-state
or thread affinity. The code compares the latest durable binding before
releasing it. A request with a single turn, a compact route, or an
opaque continuation cannot take this shortcut. The HTTP Responses
affinity parser now recognises turn-state tokens supplied as top-level
body fields or `client_metadata`, not just headers. Focused
request-level regressions verify a successful durable rebind, stale
snapshot suppression afterwards, and negative cases preserving hard
affinity. This repair is strictly precommit; it cannot replay output
that has already been sent.

**Verification on clean `af5b435`:** `make verify` fully PASS
(six-target cross-builds, installer checks, vet, and shuffled Go race
tests). Against the official pinned 0.437.11 executable with matching
source and SHA-256, the existing differential harnesses separately

**3/3**, WebSocket **13/13**, and the DeepSeek provider's

The release-only script now includes the focused 0.437.11 routing

## 0.437.11 release gate complete, including explicit absent-owner session fence

A further regression showed that a native session **explicitly released after
its active binding had already disappeared** could still be resurrected by a
lagging worker. The old `Remove` implementation returned without persisting
a release epoch when the key was missing. That is unsafe if the worker has an
older snapshot of the same session ID. The new
`TestProdex043711ExplicitAbsentSessionReleaseFencesStaleWorker` was
**RED before the fix and GREEN afterwards**.

Commit `fad1605` adds an atomic `ReleaseSessions` repository operation,
invoked for both ordinary and compact-session aliases by the explicit broker
release path. It publishes a monotonically advancing logical epoch even
when no session binding currently exists. It removes any still-present
session binding, preserves unrelated previous-response ownership, rejects
invalid digests before changing state, and persists the entire update and
last-good backup under the existing routing lock. Idempotent releases
in one second advance the logical epoch; delayed writers are rejected.
Negative-control regressions also cover malformed batch updates,
primary-snapshot corruption followed by backup recovery, and eight
concurrent stale writers attempting to reinstate a released owner.
Focused race tests for repository/routing and HTTP proxy passed.

## Tagged 0.437.11 seven-day session-fence retention and Unicode session query

Commits `d0c5046` and `0f2c2db` close two source-contract gaps
that remained after the initial 0.437.11 release-fence work.
Commit `a1f7de3` makes their regressions mandatory in the release-only
gate, alongside existing session-rotation and provider oracles.

**Retired session-release fence compaction.** The exact 0.437.11
`apply_session_release_fences` policy retains barriers for still-live
session bindings, preserves retired barriers for **seven days**, and
trims the oldest retired barriers at its default capacity
(`session_id_binding_limit=2048`, so `2048 × 4 = 8192` epochs).
Godex previously retained all epochs indefinitely and could reject
an explicit new release once 8192 expired fences were stored.

The regression first **failed on both cases**: a barrier retired eight
days earlier survived a routine persistent merge, and a full table of
eight-day-old barriers prevented a new release. After `d0c5046`,
durable snapshot writes compact both the primary and last-good backup
while preserving fences for newer live session owners and unrelated
hard previous-response bindings. Further deterministic tests verify
the exact seven-day boundary, future logical epochs, deterministic
tie-breaking by key when old retired entries have equal epochs, and
capacity eviction of recent retired entries in preference to refusing
an explicit release. Tests with 8192 actual stored fences pass.
Both repository and routing HTTP proxy shuffled race tests passed.

**Unicode session filter parity.** The 0.437.11 native session-report
matcher lowercases each field with Rust `str::to_lowercase` before the
bounded Mojo UTF-8 byte scan. The public filter **does** trim a user
query first, so existing CLI query whitespace behavior was preserved.
Godex had used `strings.ToLower`, which loses the combining dot in
`İstanbul` and does not apply contextual final sigma in `ΣΟΣ`.
Tests matching `i̇stanbul` and `σος` against those titles **failed
before the change**, while the incorrect plain-`istanbul` match was
accepted. The new `golang.org/x/text/cases.Lower(language.Und)`
adapter matches those source examples. Negative controls protect
plain/dotted I separation and the original CLI query trim behavior;
the full catalog `List` path is also covered.

## Tagged 0.437.11 Gemini tool thought-signature selection

The pinned Prodex 0.437.11 `GeminiBridgeRequestOperation::HardenToolCallThoughtSignatures`
Mojo kernel gives priority to a valid **`request.contents`** array,
falling back to root `contents` only when that nested array is absent
or invalid. It also validates a Gemini 3 tool call's thought signature
on the **model part itself**, not on its nested `functionCall` object.
Before commit `7b92594`, Godex processed only root `contents` and
incorrectly allowed a nested `functionCall.thoughtSignature` to
suppress synthetic signature injection on the containing part.
Both behaviors were captured by **failing-before** tagged regression
fixtures and now pass. Existing genuine signed model-part fields
remain unchanged; only the first tool call in each model content may
receive `skip_thought_signature_validator` when required.

The Mojo signature-presence check has its own Unicode whitespace
classifier, including the C0 separators **U+001C–U+001F**. Go's
`strings.TrimSpace` excludes these. Commit `2dcd07c` uses the exact
tagged classifier, with negative controls for an unsigned control-only
signature, a control-prefixed nonempty signed token, null, full-width
spaces, and nested function-call signatures. The C0-only regression
was **RED before** this correction, and GREEN after.

Commit `ef9e64d` makes these tagged Gemini request-kernel regressions

## Official Prodex 0.437.11 Gemini API-key executable differential (3/3)

The previous checkpoint qualified the tagged Gemini thought-signature
Mojo source contracts but did **not** compare the API-key Super Gemini
data plane against the official executable. A new isolated, loopback-only
binary differential exposed **two real mismatches** and now enforces
their corrections as release prerequisites:

1. **Outbound protocol and tool history.** The official
   `prodex super --provider gemini` API-key path sends
   `POST /v1beta/openai/chat/completions` with a normalized OpenAI
   Chat Completions request body. Godex had sent the same Responses input
   to `/v1beta/models/<model>:generateContent` using native Gemini
   `contents`. It also forwarded an unpaired assistant tool call that
   canonical Prodex removed. Commit `706212c` aligns the **API-key
   pool only** with the tagged chat-compatible request adapter,
   including adjacency repair. Direct/native Gemini transports retain
   their original GenerateContent routing.

2. **Response protocol semantics.** The outbound URL is chat-compatible,
   but the official 0.437.11 provider still decodes native Gemini
   `candidates` for the successful Responses output. An upstream
   Chat Completion-shaped JSON `choices` body with HTTP 200 is **not**
   accepted as successful model output. An initial Godex implementation
   incorrectly returned visible text as a success. After observing
   Prodex's actual binary, commits `08d0be0` and `7808885` reject that
   format with the exact tagged fallback:
   `gemini_empty_response`, id `gemini_resp_prodex`, model
   `gemini-2.5-pro`, failed status, empty output/metadata/usage,
   and **no fabricated `created_at`**. Real native Gemini candidate
   output stays on its existing translated response path.

All three behaviors were reproduced with real executable-to-executable
loopback fixtures. The request/response and orphan-tool tests were
**RED on the old Godex binary** before these fixes, and GREEN after.
The response fallback's fixed ID, model, absent timestamp and empty
metadata/usage are also asserted by a standalone strict Go regression.

Commit `d05dd12` introduces optional `tools/differential --gemini`
and registers it as a **required stage** of
`scripts/verify-release-parity.sh`. The independently pinned oracle
runs three scenarios:

- `chat-request`: single credential, exact provider URL/model/body,
  native GenerateContent response content and token usage
- `orphan-tool`: no leaked unpaired function call in upstream history,
  with a successful native Gemini response
- `chat-response`: a Chat Completion-shaped upstream body must yield
  the **exact failed Gemini Responses envelope**, not an invented
  success

The comparison retains upstream attempt counts, method, URL, synthetic
credential validity and **complete request JSON**, plus downstream
status and semantic JSON (including failure details and usage).
Only generated response IDs and observation timestamps are normalized.
Negative controls actively mutate URL, auth, model, HTTP status, output,
usage and metadata and must be detected, rather than asserting equal
but potentially invalid runs. All tests use synthetic local servers,
isolated homes, and credentials with no real provider inference.

## Gemini API-key streaming: tagged 0.437.11 executable differential (5/5)

Two further Gemini streaming mismatches were discovered through
**binary-to-binary comparison** against the exact official Prodex
0.437.11 release, rather than by inferring behavior from endpoint names.

**Native Gemini SSE on the Chat-compatible API-key path.** Tagged
Prodex posts a streaming Gemini Super request to
`/v1beta/openai/chat/completions` with
`stream_options.include_usage=true`. If the mock upstream responds
with native Gemini `candidates` SSE chunks instead of OpenAI Chat
Completions `choices`, Prodex emits only `response.created`
followed by `response.completed` with an **empty** `output` array;
it never invents visible output deltas from the native chunks.
Godex previously omitted `include_usage` and translated those native
chunks into visible `response.output_text.delta` events. A focused
public API-key pool test **failed before** the runtime fix.
Commit `48ce006` scopes the correction to API-key Super streaming,
leaving the distinct Gemini native/OAuth transport untouched. Tests
verify exact event ordering, response identity, sequential events,
no fabricated model output, and correct upstream stream options.

**Valid OpenAI Chat Completions SSE.** For two valid upstream Chat SSE
text chunks (`synthetic-`, `ok`) followed by a stop/usage chunk,
Prodex emits precisely **six** client events in order:

1. `response.created`
2. `response.output_item.added`
3. `response.output_text.delta` (`synthetic-`)
4. `response.output_text.delta` (`ok`)
5. `response.output_item.done`
6. `response.completed`

The delta and item events share the same response identity; the
completed output item has the reconstructed `synthetic-ok` text.
The terminal response retains model `gemini-3.1-pro-preview`,
`metadata.gemini.finish_reason=stop`, and input/output/total usage
totals of **2/1/3**. Godex previously emitted only four events,
omitting the item lifecycle and final usage/metadata. A dedicated
tagged regression was **RED on the old implementation**, then GREEN
after commit `d4df0e6`. The tagged Created/Completed response ID
shape is also preserved. Additional negative controls cover duplicate
termination, a broken upstream stream, identity consistency, and
noninteractive failures.

Commit `2f37ca9` required the independent **four-scenario** Gemini
executable oracle (the previous three buffered cases plus native SSE).

Godex must independently satisfy the fixture's actual stream route,
