## Tagged changes requiring qualification

The delta from `0.437.10` is a maintenance release with important
behavioral changes:

- Persistent **session release epochs** must fence stale owner snapshots after
  rotation, resume, same-second release/rebind and process restart. Immutable
  previous-response/turn-state ownership must remain protected.
- A **self-contained full-history** request may repair an old conflicting
  *soft* session routing hint. Opaque turn-state and previous-response requests
  cannot take that shortcut.
- Native TUI terminal restoration and mouse/paste/focus modes; app-server exit
  guidance and paused goals; preserved attachment and goal storage.
- Runtime doctor degraded-route and marker aggregation, provider configuration,
  DeepSeek/Gemini stream hardening, and quota rendering policy changes.

Other changes in the tagged diff move Rust policy decisions to compiled Mojo
without necessarily changing observable behavior. Audit such changes for exact
semantic deltas rather than copying code structure.

## Implementation checkpoints: session release and full-history recovery

Commits `aa30aa9` and `af5b435` implement two behavioral fixes from
the 0.437.11 tagged release notes.

**Durable session release:** Godex's version-1 routing snapshot now
retains a separate `session_release_epochs` map, atomically with the
active routing bindings and backup. An explicit deletion of a persisted
session binding installs a monotonically advancing logical fence. Old
worker snapshots cannot reinsert a session owner whose binding epoch
predates that release, while a subsequent **verified** upstream owner
may rebind with an epoch strictly above the barrier, including repeated
rotations in the same wall-clock second. The previous-response and
turn-state bindings are not silently discarded, and genuine conflicts
with no release still fail closed. The new snapshot field is optional
when loading legacy version-1 state.

Repository regressions failed before the fix on stale replay after
rebind and repeated same-second release/rebind, and now pass. Separate
tests verify a genuine unreleased conflict, backup restoration, invalid
release epochs, and rejection of malformed stale/verified updates.
The release fence is bounded by the existing routing snapshot size and
entry-count limits, but Godex has **not yet reproduced** the tagged
Prodex compaction policy for seven-day expired retired fences.

**Full-history soft conflict:** the Responses preflight now releases a
genuinely conflicted *soft session* only when its input has
reconstructable full history and no hard previous-response, turn-state
or thread affinity. The code compares the latest durable binding before
releasing it. A request with a single turn, a compact route, or an
opaque continuation cannot take this shortcut. The HTTP Responses
affinity parser now recognises turn-state tokens supplied as top-level
body fields or `client_metadata`, not just headers. Focused
request-level regressions verify a successful durable rebind, stale
snapshot suppression afterwards, and negative cases preserving hard
affinity. This repair is strictly precommit; it cannot replay output
that has already been sent.

**Verification on clean `af5b435`:** `make verify` fully PASS

## 0.437.11 release gate complete, including explicit absent-owner session fence

A further regression showed that a native session **explicitly released after
its active binding had already disappeared** could still be resurrected by a
lagging worker. The old `Remove` implementation returned without persisting
a release epoch when the key was missing. That is unsafe if the worker has an
older snapshot of the same session ID. The new
`TestProdex043711ExplicitAbsentSessionReleaseFencesStaleWorker` was
**RED before the fix and GREEN afterwards**.

Commit `fad1605` adds an atomic `ReleaseSessions` repository operation,
invoked for both ordinary and compact-session aliases by the explicit broker
release path. It publishes a monotonically advancing logical epoch even
when no session binding currently exists. It removes any still-present
session binding, preserves unrelated previous-response ownership, rejects
invalid digests before changing state, and persists the entire update and
last-good backup under the existing routing lock. Idempotent releases
in one second advance the logical epoch; delayed writers are rejected.
Negative-control regressions also cover malformed batch updates,
primary-snapshot corruption followed by backup recovery, and eight
concurrent stale writers attempting to reinstate a released owner.
Focused race tests for repository/routing and HTTP proxy passed.
